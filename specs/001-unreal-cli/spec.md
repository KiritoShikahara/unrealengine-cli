# 機能仕様: Unreal Engine 用エージェント操作 CLI(unreal-cli)

**Feature Branch**: `001-unreal-cli`

**Created**: 2026-10-14

**Status**: Draft

**Input**: ユーザー記述: 「unity-cli(Unity を Claude Code などのエージェントから操作できる CLI)と同じ使い勝手と品質で、Unreal Engine 版を作りたい。範囲は unity-cli と同等の全機能。既存の ue-cli は参考にするが、新規に作る。2つのリポジトリ間に依存関係は持たせない」

## Clarifications

### Session 2026-10-14

- Q: CLI の名前は? → A: `unreal-cli`
- Q: 対応する UE バージョンは? → A: 5.5〜5.8
- Q: 実装言語と通信方式は? → A: Rust 製 CLI と、ローカル TCP 上の JSON
- Q: 主な対応 OS は? → A: Windows を本命とし、macOS / Linux は CLI 単体の動作だけを保証する
- Q: MCP サーバーモードは? → A: 最初の版から含める

## 位置づけと独立性

- 本プロジェクトは新規リポジトリとして単独で成立する。unity-cli・既存 ue-cli のコード、パッケージ、ビルド成果物、設定、ドキュメントへの参照や依存を持たない。
- 両者は「機能の範囲と品質水準」を決めるときの参考にだけ使う。コードのコピーはしない。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - エディタに接続して状態を確認する (Priority: P1)

エージェント(Claude Code、Codex など)が CLI を 1 回実行し、起動中の Unreal Editor に接続する。疎通、エディタのバージョン、プロジェクト名、ログを取得する。

**Why this priority**: 他のすべての機能はエディタとの通信路の上に成り立つため。

**Independent Test**: プラグイン導入済みのプロジェクトでエディタを起動し、`ping` と `logs` を実行すると JSON で結果が返る。

**Acceptance Scenarios**:

1. **Given** エディタとプラグインが起動している、**When** `ping` を実行する、**Then** 応答時間とエディタ情報が JSON で返り、終了コードが 0 になる。
2. **Given** エディタが起動していない、**When** 任意のエディタ操作コマンドを実行する、**Then** 原因と次の手順(エディタの起動方法)を示す構造化エラーが返り、0 以外の終了コードになる。

---

### User Story 2 - プロジェクトへの導入とエディタの起動・ビルド (Priority: P1)

ユーザーまたはエージェントが、対象の .uproject に対してセットアップを 1 コマンドで実行する。エディタ側プラグインの配置と有効化、エディタターゲットのビルド、エディタの起動と待機までを行う。

**Why this priority**: 導入できなければ利用を始められないため。

**Independent Test**: プラグイン未導入の空プロジェクトに setup → open を実行すると、`ping` が成功する状態になる。

**Acceptance Scenarios**:

1. **Given** プラグイン未導入のプロジェクト、**When** setup を実行する、**Then** プロジェクトを変更する前に変更内容を表示し、変更後にビルド結果(エラーはファイル・行・メッセージ)を返す。
2. **Given** `--dry-run` を付けた、**When** setup を実行する、**Then** ファイルを一切変更せずに予定の変更だけを表示する。

---

### User Story 3 - Blueprint の読み書き・コンパイル・保存 (Priority: P1)

エージェントが Blueprint の変数・グラフ・ノード・ピン接続を読み、ノード追加・接続・値設定・コンパイル・保存を行う。

**Why this priority**: UE で最も頻繁に行う編集作業で、エージェント利用の中心となるため。

**Independent Test**: テスト用 Blueprint に「BeginPlay → Print String」を追加し、コンパイルエラー 0 で保存できる。

**Acceptance Scenarios**:

1. **Given** 既存の Blueprint、**When** グラフを読む、**Then** ノード・ピン・接続が安定した ID 付きで返る。
2. **Given** コンパイルエラーのある Blueprint、**When** 保存する、**Then** 強制指定がない限り保存を拒否し、エラー内容を返す。

---

### User Story 4 - レベル・アクター・アセットの操作 (Priority: P2)

エージェントがレベル上のアクターを一覧・生成・変更・削除し、アセットを検索・作成・変更・保存する。リフレクションを通じて任意のプロパティを読み書きする。

**Why this priority**: シーン構築とアセット管理は Blueprint 編集に次いで利用頻度が高いため。

**Independent Test**: 新規レベルにアクターを生成してプロパティを変更し、保存して再読み込みすると値が保持されている。

**Acceptance Scenarios**:

1. **Given** 開いているレベル、**When** アクターを生成する、**Then** 名前・クラス・位置が返り、操作はエディタ上で取り消せる。
2. **Given** 存在しないプロパティ名、**When** 値を設定する、**Then** 候補名を含むエラーが返る。

---

### User Story 5 - C++ コードの編集と反映 (Priority: P2)

エージェントがプロジェクトの C++ ソースを検索・読み取り・編集し、変更内容に応じて最も安い反映方法(Live Coding か、エディタ再起動を伴うフルビルドか)を自動で選んで適用する。コンパイルエラーは構造化して返す。

**Why this priority**: C++ プロジェクトでの開発ループに必須なため。

**Independent Test**: .cpp だけを変更するとホットリロードで、ヘッダーを変更するとフルビルドで反映され、どちらの場合も結果が返る。

**Acceptance Scenarios**:

1. **Given** .cpp だけの変更、**When** 反映を実行する、**Then** Live Coding で反映し、エディタは再起動しない。
2. **Given** 未保存アセットがある状態でフルビルドが必要、**When** 反映を実行する、**Then** 強制指定がない限り中止し、未保存アセットの一覧を返す。

---

### User Story 6 - PIE 実行と自動テスト (Priority: P2)

エージェントが Play In Editor を指定秒数、または特定のログが出るまで実行し、エラーと警告を回収する。UE の Automation Test を実行し、結果を構造化して返す。

**Why this priority**: 変更を検証して完了を判断するために必要なため。

**Independent Test**: PIE を 5 秒実行するとエラー件数が返る。テストフィルタを指定して Automation Test を実行すると、合否の一覧が返る。

**Acceptance Scenarios**:

1. **Given** 実行時エラーを出すレベル、**When** PIE を実行する、**Then** エラーが件数と本文付きで返る。

---

### User Story 7 - 専門領域の操作 (Priority: P3)

エージェントが、アニメーション(AnimBP、ステートマシン、Montage、BlendSpace)、UMG ウィジェット、マテリアル、Niagara、ランドスケープ、Enhanced Input、データテーブル/データアセット、オーディオ、Sequencer、コンポーネント、インターフェース、パッケージングを操作する。

**Why this priority**: 機能の範囲を unity-cli と同等にするためには必要だが、基盤が揃ってから順に追加できるため。

**Independent Test**: 領域ごとに「作成 → 変更 → 保存 → 再読込で確認」の E2E が通る。

**Acceptance Scenarios**:

1. **Given** 専用コマンドがない操作、**When** エディタ内スクリプト実行(Python)を使う、**Then** 出力・例外・ログが構造化して返る。

---

### User Story 8 - エージェント向けスキルとツール探索 (Priority: P2)

ユーザーがプロジェクトにエージェント用スキルを導入する。エージェントは、必要になった時点でだけスキルとツールの説明を読み込み、文脈を圧迫せずに 100 個以上のツールを使い分ける。

**Why this priority**: エージェントがツールを正しく選べることが、使い勝手を決めるため。

**Independent Test**: `skills install claude-code --local` で `.claude/skills/` にスキルが配置される。`skills lint` が通る。ツール検索でキーワードから該当ツールとその入力スキーマが返る。

**Acceptance Scenarios**:

1. **Given** エディタ未起動、**When** スキルを導入する、**Then** エディタやネットワークへの接続なしで完了する。
2. **Given** MCP 対応クライアント、**When** MCP モードで起動する、**Then** 同じツール群が MCP ツールとして公開される。

---

### User Story 9 - 配布・インストール・自動更新 (Priority: P3)

ユーザーが 1 行のインストールスクリプト、またはパッケージマネージャで CLI を導入する。更新はチェックサムで検証してから適用する。

**Why this priority**: 公開配布のために必要だが、ローカル開発では後回しにできるため。

**Independent Test**: クリーン環境でインストールスクリプトを実行すると CLI が PATH に入る。チェックサムが不一致なら導入を中止する。

**Acceptance Scenarios**:

1. **Given** 改ざんされたリリース成果物、**When** インストールする、**Then** 導入を中止し、既存のバイナリには触れない。

---

### Edge Cases

- 同じマシンで複数のエディタ(別プロジェクト/別バージョン)が起動している → インスタンスを一覧し、プロジェクトパスで接続先を選べる。
- エディタがシェーダーコンパイル中やモーダルダイアログ表示中で応答しない → タイムアウト後に状態を説明するエラーを返す。
- ビルド中にエディタが起動している → ビルドを始める前に検出して停止する。
- 長時間の処理(ビルド、パッケージング、大量インポート) → ジョブとして非同期実行し、進捗の取得とキャンセルができる。
- エディタ内スクリプトが無限ループする → タイムアウトでジョブを中止する。
- 対応外の UE バージョン → 接続時にバージョン不一致を明示する。
- パスに日本語や空白を含むプロジェクト → 正しく扱える。

## Requirements *(mandatory)*

### Functional Requirements

**基盤**

- **FR-001**: CLI は単一の実行ファイルとして動作しなければならない(MUST)。
- **FR-002**: すべてのコマンドは、テキスト出力と JSON 出力(`--output json`)の両方に対応しなければならない(MUST)。JSON の形は全コマンドで共通(成功/失敗、データ、エラーコード、エラーメッセージ、次の手順)とする。
- **FR-003**: 終了コードは、成功・利用者の入力誤り・接続失敗・エディタ側の失敗・タイムアウトを区別しなければならない(MUST)。
- **FR-004**: CLI はローカルのエディタ内プラグインとローカル通信で接続しなければならない(MUST)。外部ネットワークに公開してはならない。
- **FR-005**: 起動中のエディタインスタンスを検出し、一覧表示と接続先の選択ができなければならない(MUST)。
- **FR-006**: 変更を伴うコマンドは `--dry-run` に対応しなければならない(MUST)。
- **FR-007**: エディタ上の変更は、エディタの取り消し(Undo)単位として記録しなければならない(MUST)。
- **FR-008**: 長時間の処理はジョブとして実行し、状態取得・ログ取得・キャンセルができなければならない(MUST)。

**導入・ライフサイクル**

- **FR-010**: setup はプロジェクトにエディタ側プラグインを配置して有効化し、変更前に変更内容を表示しなければならない(MUST)。
- **FR-011**: エディタターゲットのビルド、エディタの起動と待機、終了ができなければならない(MUST)。ビルドエラーはファイル・行・コード・メッセージに分解して返す。
- **FR-012**: 環境診断コマンド(doctor)で、エンジンの場所、プラグインのバージョン、接続、ビルドツールの有無を確認できなければならない(MUST)。

**エディタ操作(ツール API)**

- **FR-020**: Blueprint: 変数・関数・イベント・グラフ・ノード・ピンの読み取りと、追加・削除・接続・値設定・コンパイル・保存。
- **FR-021**: レベル/アクター: 一覧・生成・変更・削除・選択・トランスフォーム・レベルの新規作成/保存/読み込み。
- **FR-022**: アセット: 検索・作成・複製・移動・削除・インポート・保存・参照関係の取得。
- **FR-023**: リフレクション: 任意のアセット・オブジェクト・アクター・コンポーネントの編集可能なプロパティを、名前で読み書きできること。
- **FR-024**: C++: ソースの検索・読み取り・編集、Live Coding とフルビルドの自動選択、構造化されたコンパイルエラー。
- **FR-025**: 実行と検証: PIE の実行(秒数指定/ログ条件で停止)、Automation Test の実行と結果取得、エディタログの取得(重要度・カテゴリ・続きから)。
- **FR-026**: 専門領域: アニメーション、UMG、マテリアル、Niagara、ランドスケープ、Enhanced Input、データテーブル/データアセット、オーディオ、Sequencer、コンポーネント、インターフェース、パッケージング。
- **FR-027**: 汎用実行: エディタ内で Python を実行し、出力・例外・ログを返せること。
- **FR-028**: ツールの総数は unity-cli と同等(100 個以上)とし、ツール一覧と検索(名前・説明・グループ)で各ツールの入力スキーマを取得できること。

**エージェント連携**

- **FR-030**: 用途別スキルを同梱し、Claude Code / Codex / Cursor / Windsurf / VS Code の各形式で、プロジェクト単位とユーザー単位で導入・更新・削除できなければならない(MUST)。導入時にエディタやネットワークへの接続を必要としない。
- **FR-031**: スキルは共通の契約(形式・必須項目)に従い、静的検証コマンド(`skills lint`)で検証できなければならない(MUST)。
- **FR-032**: MCP サーバーモードで、同じツール群を MCP ツールとして公開できなければならない(MUST)。
- **FR-033**: 公式ドキュメントとエンジンソースをローカルで参照できる仕組みを提供すべきである(SHOULD)。対象と取得方法は計画で決める。

**配布**

- **FR-040**: Windows・macOS・Linux 向けのリリース成果物を提供し、インストールスクリプトはチェックサムを検証してから導入しなければならない(MUST)。
- **FR-041**: 自動更新はチェックサムで検証し、環境変数で無効にできなければならない(MUST)。

**品質**

- **FR-050**: 自動テストは必須とする(MUST)。CLI 側のユニットテスト・統合テストと、実エディタを使う E2E テストを用意し、TDD(テストを先に書き、失敗を確認してから実装)で進める。
- **FR-051**: フォーマット、静的解析(警告ゼロ)、全テスト、スキルの静的検証を CI の必須ゲートにしなければならない(MUST)。
- **FR-052**: ドキュメント(README 日英、アーキテクチャ、ツールカタログ、スキルガイド、エディタ互換表)を整備しなければならない(MUST)。

### Key Entities

- **エディタインスタンス**: 起動中の Unreal Editor。プロジェクトパス、エンジンバージョン、接続先、状態を持つ。
- **ツール**: エディタ操作の単位。名前、グループ、説明、入力スキーマ、出力スキーマを持つ。
- **ジョブ**: 長時間処理。ID、種類、状態、進捗、ログ、結果を持つ。
- **スキル**: エージェント向けの手順書。名前、発動条件、使うツール、本文を持つ。
- **結果エンベロープ**: 全コマンド共通の出力形式。成功/失敗、データ、エラーコード、次の手順を持つ。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: プラグイン未導入のプロジェクトから、setup → エディタ起動 → `ping` 成功までを 1 コマンドずつ、ドキュメントを読まずに 10 分以内(初回のシェーダーコンパイル時間を除く)で完了できる。
- **SC-002**: エディタ接続済みの状態で、単発ツール呼び出しの応答(CLI 起動を含む)の 95 パーセンタイルが 300ms 以下である。
- **SC-003**: 公開ツールが 100 個以上あり、すべてに入力スキーマと少なくとも 1 本の自動テストがある。
- **SC-004**: 対応する全 UE バージョンで、受け入れ E2E(User Story 1〜6 の受け入れシナリオ)が 100% 成功する。
- **SC-005**: エージェントが代表タスク 10 件(例: 「BeginPlay で文字を表示する Blueprint を作る」)を、人の介入なしで 9 件以上完了する。
- **SC-006**: すべての失敗レスポンスに、エラーコードと次の手順が含まれる。

## Assumptions

- 対象の UE バージョンは 5.5〜5.8 とする。
- 主な開発・検証環境は Windows とする。エディタ E2E は Windows だけで行い、macOS / Linux は CLI 単体の動作(導入、スキル、オフライン機能)だけを保証する。
- エディタ側プラグインは C++ の Editor プラグインとして実装し、Python Editor Script Plugin を利用できる前提とする。
- CLI は Rust で実装し、エディタとはローカル TCP 上の JSON で通信する。配布チャネルは plan で決める。
- 本リポジトリは unity-cli・ue-cli と独立して公開・保守する。
